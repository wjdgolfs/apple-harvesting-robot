## 3. 데이터 연결과 실행 흐름

```text
익음도 ZIP + Amodal ZIP
  → 사진명·크기·CRC32 대조 + 분할별 SHA-256 표본 확인
  → 동일 다각형 좌표 연결 → 영역별 apple_id 확보

익음도 RGB + VIA JSON
  → 원본 프레임 그룹마다 대표 사진 선택 → 색 점수 계산
  → 사과 ID별로 한 분할만 유지 → 학습 임계값 재계산 → 평가

Amodal ZIP의 가시/전체 윤곽
  → 자연 가림률 및 품질 검사 → 익음도 결과와 연결
  → 동일 영역에 합성 잎 0/15/30/50% 적용 → 성능 변화 측정

무게 JPG 폴더
  → 60개 사과 × 72개 조건 검수 → 사과마다 고정 조건 1장 선택
  → 사과 단위 학습/평가 분리 → 면적 회귀 및 합성 가림 비교
```

익음도 자료 4,027장 중 Amodal 자료와 사진명·크기·CRC32가 같은 사진은 3,925장이다. SHA-256 전체 검사가 아니라 분할별 1장씩 추가 확인한다. 유일하게 대응하는 윤곽 15,271건에 ID를 연결하고 가림 쪽 미연결/모호한 윤곽 64건은 제외한다.

원 배포 분할에는 같은 ID 문자열이 학습/평가에 291개 겹친다. `fruit_id_check.py`는 ID의 해시로 원래 존재하던 분할 중 하나만 선택하고 다른 분할의 관측을 버린다. 앞 단계의 원본 프레임 그룹 분리도 유지한다. 최종 결과는 학습 895영역, 검증 338영역, 평가 202영역이다. 검증셋으로 임계값을 고르지는 않고 학습셋의 균형 정확도로 정한다.

ID 문자열은 데이터셋에서 주어진 식별자다. 연결된 594개 ID 중 139개에 익음/미숙 라벨이 모두 나타난다. 코드가 사진별 원래 라벨을 보존하는 것은 확인했지만, 동일 실물의 시간 변화인지 ID 재사용인지까지 이 커밋만으로 확정할 수 없다.

## 5. 무게 알고리즘과 성능 해석

전체 4,320장은 데이터 검수 대상이다. 실제 회귀는 사과마다 `spb/int/me/ver` 고정 조건의 사진 1장을 골라 60장으로 수행한다. 카메라별 20개 사과를 16개 학습/4개 평가로 나눠 총 48개/12개를 사용한다. 같은 사과의 다른 72장 촬영분도 manifest상 같은 분할이다.

`fruit_pixels()`는 화면 중앙 ROI에서 `R-B >= 30`, `G-R <= 9`에 해당하는 색 영역을 잡는다. 특징은 `(마스크 면적 / 전체 이미지 면적)^1.5`이며, 무게는 `절편 + 기울기 × 특징`으로 계산한다. 실제 거리·동전 크기·깊이를 이용한 물리적 보정은 없다. 파일명 무게는 학습 정답이며 이미지 특징으로 직접 넣지 않는다.

| 원본 조건, 평가 사과 12개 | MAE |
|---|---:|
| 전체 학습 평균 무게 | 46.77g |
| 카메라를 합친 이미지 면적 회귀 `pooled_clean` | 36.52g |
| 카메라별 학습 평균 무게 | 12.92g |
| 카메라별 이미지 면적 회귀 `clean` | 12.46g |

카메라별 무게 범위는 iPhone 11 108.63~157.36g, iPhone 8 196.38~221.75g, LM-X430 248.73~320.09g으로 서로 겹치지 않는다. 카메라 정보만으로도 무게대가 드러나므로 12.46g을 일반적인 영상 무게 추정 성능으로 제시하면 과장이다. 저자도 이 영향을 문서에 명시하고 이미지 기반 비교값을 36.52g으로 구분했다. 카메라 평균 대비 회귀의 추가 개선은 약 0.46g에 그친다.

이 데이터에서 36.52g도 카메라·크기·촬영 조건 영향을 받는 결과다. 새 과수원, 거리, 장치에서의 성능을 보장하지 않으며 반복 분할이나 신뢰구간은 제공하지 않는다.

## 6. 자연 가림과 합성 가림의 차이

자연 가림은 가시 마스크 V와 추정 전체 마스크 A를 이용한 `1 - |V∩A|/|A|`다. 단순 `1-|V|/|A|`는 주석 불일치로 69건에서 음수가 나와 교집합 방식으로 계산한다. 전체 윤곽이 100px 패딩을 제외한 내부에 있고, 가시 픽셀의 전체 윤곽 밖 비율이 10% 이하인 관측만 유효 처리한다.

15,335개 대응 영역 중 11,173개가 유효하고 가림률 중앙값은 45.93%다. 이 기능은 전체 윤곽 정답이 있는 데이터의 통계다. 현장에서 가시 마스크만 받아 전체 윤곽을 복원하는 모델은 구현돼 있지 않다.

합성 가림의 분모는 원래 보이던 사과 면적이다. 따라서 추가 가림 0%도 원본의 자연 가림을 포함하고, 추가 30%가 전체 과실의 자연 가림 30%를 의미하지 않는다. 한 샘플의 각도·위치·색은 해시/시드로 고정하고 잎 크기를 이분 탐색해 가림량을 맞춘다.

| 추가 가림 | 원본 학습 익음 발견 / 20 | 이미지 면적 회귀 MAE | 증강 학습 면적 회귀 MAE |
|---|---:|---:|---:|
| 0% | 17 | 36.52g | 41.37g |
| 15% | 8 | 39.15g | 39.40g |
| 30% | 0 | 42.15g | 39.21g |
| 50% | 0 | 48.66g | 42.78g |

녹색 도형이 색 점수와 색 마스크를 직접 바꾸는 실험이다. 실제 잎의 질감·그림자·다양한 위치, 여러 시드, 동영상의 움직임까지 검증한 결과는 아니다. 증강은 50% 가림 무게 오차를 낮췄지만 원본 오차는 커졌고, 익음도는 30%부터 증강 모델도 균형 정확도 50%다. 가림 강건성이 해결됐다고 해석하기 어렵다.

## 7. 기존 코드와 통합할 때 필요한 작업

1. **검출 결과 변환:** 현재 `predict_pretrained.py:54`는 `prediction_index`와 실수 박스 `xmin/ymin/xmax/ymax`, 별도 다각형 JSON을 출력한다. 문서 제안은 검수 코드의 `id/xmax_inclusive/ymax_inclusive` 기준이다. 예측 인덱스·다각형 순서·좌표를 함께 변환하고 원본 해상도의 인스턴스 마스크를 구성하는 어댑터가 필요하다. YOLO의 실수 좌표에 검수 마스크 규칙의 `+1`을 일괄 적용하면 안 된다.
2. **데이터 연결 방식 교체:** `link_annotations.py`는 두 배포본의 다각형 좌표가 정확히 같아야 연결된다. 새 검출 다각형과 정답을 연결하는 일반 매칭기가 아니다. 실측 평가에는 IoU 등으로 대응시키는 절차가 필요하다.
3. **호출 인터페이스:** 학습·평가 CLI에서 점수/회귀 계산을 분리해 객체별 RGB·박스·마스크를 받는 함수를 만들고 학습 임계값·계수를 저장/로드해야 한다. 현재 스크립트는 실행마다 실험을 다시 구성한다.
4. **현장 데이터 확보:** 무게는 거리/기준물/깊이 보정 및 현장 실측 무게가 필요하다. 자연 가림률은 추정 전체 윤곽이나 복원 모델이 마련되기 전까지 결측 처리한다.
5. **수확 판단 검증:** 익음 정밀도와 재현율을 함께 평가하고 검출 누락까지 포함한다. 판단 보류 사유·신뢰도·가림 임계값은 문서 제안이며 런타임 기능은 아직 없다. 색 점수 자체도 확률이 아니다.
6. **객체 ID 범위:** 현재 예측 인덱스는 한 이미지 안의 번호다. 여러 프레임에서 같은 사과를 추적하는 영속 ID 기능은 별도로 구현해야 한다.

## 8. 코드 품질과 재현 시 주의점

검수와 실험을 구분하고, 정답/예측을 CSV로 남기며, 학습 자료만으로 임계값·회귀를 맞추는 점은 후속 비교에 유용하다. 분할 중복을 실제로 검사해 예외를 발생시키고, 합성 가림의 목표/실측 비율을 둘 다 저장한다. 실패 사례와 데이터 편향도 문서에 기록돼 있다.

재현 입력은 별도 데이터 폴더의 `ripeness/`, `weight/Fuji_1/`, `weight/Fuji_2/`, `archive.zip`, `02-annotated_data_fuji.zip`이다. 외부 Python 라이브러리는 이 실험 코드 기준 Pillow를 사용한다. 기록된 환경은 Python 3.11.9/Pillow 12.3.0이며, 실험 전용 잠금 파일은 없다. 일부 VIA 읽기 함수는 최상위 JSON 래퍼나 regions의 list/dict를 모두 지원하지만 다른 함수는 특정 형식을 가정한다. 다른 배포 버전에는 공통 로더가 필요하다.

`reproduce.py`는 계산 결과와 작업별 예시 3종을 생성하지만 `결과사진/`의 발표용 6장 전체를 구성하지 않는다. 특히 02·03·05번 이미지의 별도 제작 코드는 이 커밋에서 확인되지 않는다. 계산 실험 재현과 발표 이미지 전체 재생성을 구분해야 한다.
